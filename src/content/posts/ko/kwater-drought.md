## 초록

6개월 표준강수지수(SPI6)를 6단계 가뭄 등급으로 이산화하고, 기상·수문 변수로 해당 등급을 분류하는 문제를 다뤘다. 기상청 ASOS 일자료와 지점별 SPI6, 일강수량에서 만든 누적강수량, K-water 다목적댐·용수댐 일자료를 Oracle에서 지점·일자 기준으로 조인했다. 첫 모델은 Oracle `DBMS_DATA_MINING`의 `ALGO_RANDOM_FOREST`로 만들어 기간·변수 조합을 비교했고, 클래스별 지표와 하이퍼파라미터 탐색이 필요해진 단계에서 R `randomForest`·`caret`으로 옮겼다. 후보 변수 12개를 정보 획득량과 예측 시점 입력 가능성 기준으로 5개로 줄이고 변수별 정규화·표준화를 적용했다. 발표 기준 최종 모델은 47,098건(학습 42,392 / 테스트 4,706)에서 정확도 96.1%, F1 0.933, AUC 0.955를 기록했고, 입력값에 대한 가뭄 단계별 확률을 보여주는 R Shiny 대시보드로 제공했다. 공모전 결과는 장려상이다.

## 1. 문제 정의

- 과제: 댐·지점의 하루 단위 기상·수문 상태로 SPI6 기준 가뭄 등급을 분류하고, 대시보드에서 단계별 확률을 보여준다.
- 입력: 누적강수량, 가조시간, 평균기온, 저수량, 유효저수량(최종 5개).
- 출력: 6개 클래스와 클래스별 확률(`predict(..., type = 'prob')`).
- 타깃: SPI6 연속값을 SQL `UPDATE`로 구간화했다.

| 등급 | SPI6 구간 |
|---|---|
| 심한습윤 | `spi6 >= 1.50` |
| 보통습윤 | `1.00 <= spi6 < 1.50` |
| 정상 | `-1.00 < spi6 < 1.00` |
| 약한가뭄 | `-1.50 < spi6 <= -1.00` |
| 보통가뭄 | `-2.00 < spi6 <= -1.50` |
| 심한가뭄 | `spi6 <= -2.00` |

`code/sql/03_랜포_14-23.sql`에서는 습윤 두 단계를 `습윤` 하나로 합친 5단계를 시험했지만, 최종 데이터셋과 Shiny 코드의 라벨은 6단계다.

- 평가 지표: Oracle 단계는 테스트셋 정확도만 계산했다. R 단계에서는 클래스 불균형(정상 68.2%, 심한가뭄 1.9%) 때문에 혼동행렬 기반 클래스별 F1과 매크로·마이크로 평균 F1을 주 지표로 썼다.

```text
precision_c = TP_c / (TP_c + FP_c)
recall_c    = TP_c / (TP_c + FN_c)
F1_c        = 2 * precision_c * recall_c / (precision_c + recall_c)
macro_F1    = mean_c(F1_c)
```

  보조 지표는 `caret::confusionMatrix`의 민감도·특이도·정밀도와 `pROC::multiclass.roc`의 다중 클래스 AUC다(`code/R/06_SPI_성능평가_F1_ROC.R`).
- 제약: 대시보드 사용자가 입력할 수 있는 값만 변수로 쓴다. 방류량처럼 댐 운영 결과로 정해지는 값은 제외 대상이다.

## 3. 방법

### 3.1 전체 파이프라인

```text
[기상청 ASOS 일자료]  [기상청 SPI6]  [일강수량 → 6개월 누적강수량]  [K-water 댐 일자료]  [지하수 수위]
          └──────────────┴───────────────┬──────────────┴────────────────────┘
                                         ▼
                     Oracle: 지점명 정규화 → (일시, 지점명) 조인 → NULL 행 삭제
                                         ▼
                     Oracle: SPI6 → 가뭄 등급 (UPDATE, 6단계)
                                         ▼
                     Oracle DBMS_DATA_MINING: ALGO_RANDOM_FOREST, 정확도 비교
                     (기간 19-22 / 14-23 / 18-22, 저수량·행정구역·수위·방류량 추가)
                                         ▼
                     CSV export → R
                     ├─ 변수 선택: 12개 → 5개 (정보 획득량 + 입력 가능성)
                     ├─ 스케일링: min-max(가조시간, 평균기온), z-score(저수량, 누적강수량)
                     ├─ 9:1 층화 분할 (createDataPartition)
                     ├─ ntree 1~100 탐색, 매크로 F1
                     └─ 평가: 클래스별 F1, 민감도, 특이도, 정밀도, 다중 클래스 AUC
                                         ▼
                     R Shiny: 유역·댐 선택 → 입력 스케일링(학습셋 통계) → 단계별 확률 막대그래프
```

Oracle에서 통합·라벨링·첫 모델 비교까지 하고, 지표와 하이퍼파라미터 탐색이 필요한 단계부터 R로 옮겼다. 대시보드는 앱 시작 시 같은 데이터로 모델을 다시 학습해 쓴다.

### 3.2 SQL 라벨링

등급 컬럼은 SPI6 테이블에 `alter table ... add`로 추가하고 구간별 `UPDATE`로 채웠다.

`code/sql/02_랜포_19-22.sql`

```sql
alter table drou add 가뭄 varchar2(20);
update drou
    set 가뭄 = '심한습윤'
    where spi6 >= 1.50;
update drou
    set 가뭄 = '보통습윤'
    where spi6 >= 1.00 and spi6 < 1.50;
update drou
    set 가뭄 = '정상'
    where spi6 > -1.00 and spi6 < 1.00;
update drou
    set 가뭄 = '약한가뭄'
    where spi6 > -1.50 and spi6 <= -1.00;
update drou
    set 가뭄 = '보통가뭄'
    where spi6 > -2.00 and spi6 <= -1.50;
update drou
    set 가뭄 = '심한가뭄'
    where spi6 <= -2.00;
commit;
```

모델 입력에는 `가뭄`만 넣고 `spi6`는 넣지 않았다. R(`07_랜포_트리수별_F1_비교.R`)에서도 `spi[, -c(1, 2, 4, 8, 9, 10, 13, 14)]`로 SPI6 컬럼을 제거해 타깃의 원천 값이 입력에 섞이지 않게 했다.

### 3.3 Oracle DBMS_DATA_MINING 랜덤포레스트

데이터가 이미 Oracle에 있었기 때문에 첫 모델은 DB 안에서 만들었다. `DBMS_DATA_MINING.GET_DEFAULT_SETTINGS`를 복사한 설정 테이블에 알고리즘 이름과 자동 전처리 옵션을 넣는다.

`code/sql/04_랜포_저수량포함_최종.sql`

```sql
BEGIN
   INSERT INTO SETTINGS_GLM
        VALUES (DBMS_DATA_MINING.ALGO_NAME, 'ALGO_RANDOM_FOREST');

   INSERT INTO SETTINGS_GLM
        VALUES (DBMS_DATA_MINING.PREP_AUTO, 'ON');

   INSERT INTO SETTINGS_GLM
        VALUES (
                  DBMS_DATA_MINING.GLMS_REFERENCE_CLASS_NAME,
                  'GLMS_RIDGE_REG_DISABLE');

   COMMIT;
END;
```

이후 `DBMS_DATA_MINING.CREATE_MODEL`(`CLASSIFICATION`, case id `ID`, target `가뭄`)로 모델을 만들고, `PREDICTION(MD_CLASSIFICATION_MODEL4 USING *)`과 실제값의 일치 비율로 테스트 정확도를 계산했다. 설정 테이블 이름 `SETTINGS_GLM`은 GLM용 템플릿을 재사용하고 `ALGO_NAME`만 바꾼 흔적이다. `PREP_AUTO = ON`이면 범주형 변수 인코딩 같은 전처리를 Oracle이 맡는다.

학습/테스트 분할은 `rownum` 기반 `id` 임계값으로 했다. `02`, `03`은 조인 결과 순서 그대로 `id < 73000`, `id < 170000`으로 잘랐고, `04`부터는 `ORDER BY DBMS_RANDOM.VALUE`로 섞은 테이블에 `rownum`을 다시 붙인 뒤 `id < 37700`(04), `id < 25791`(05)로 나눴다.

SQL로는 정확도는 쉽게 나오지만 클래스별 F1, AUC, 트리 수 변화는 매번 쿼리를 새로 짜야 했고, 하이퍼파라미터를 바꿀 때마다 설정 테이블 수정과 `DROP_MODEL`/`CREATE_MODEL`을 반복해야 했다. 이 비용 때문에 R로 옮겼다.

### 3.4 변수 선택: 12개 → 5개

개선 전 후보는 누적강수량, 저수량, 가조시간, 방류량, 평균지면온도, 평균기온, 댐 이름, 평균상대습도, 합계일조시간, 계절, 행정구역, 강유역의 12개다. 발표자료(`docs/SPI6_가뭄예측_발표자료.pdf`)의 선정 기준은 "정보 획득량이 높은 변수 중 예측 가능한 변수"다.

| 변수 | 처리 | 근거 |
|---|---|---|
| 누적강수량, 저수량, 가조시간, 평균기온 | 유지 | 정보 획득량 상위, 사용자 입력 가능 |
| 유효저수량 | 추가 | 댐 선택 시 고정되는 댐 제원 |
| 방류량 | 제외 | 순위 4위지만 댐 운영 결과라 예측 입력으로 부적합 |
| 평균지면온도, 댐 이름, 평균상대습도, 합계일조시간 | 제외 | 개별 제외 사유 기록 없음 |
| 계절, 행정구역, 강유역 | 제외 | 순위 하위 3개 |
| 지하수 수위 | 제외 | 결측으로 표본 수 감소 |

12개 나열 순서는 발표자료 그림 기준이다. 정보 획득량 계산 코드는 레포에 없다.

### 3.5 스케일링과 분할

가조시간·평균기온은 min-max 정규화, 저수량·누적강수량은 z-score 표준화를 적용했다. 분할은 `caret::createDataPartition(spi$가뭄, p = 0.9)`로 등급 비율을 유지하는 9:1 층화 분할이다(`code/R/08_랜포_표준화_최종_F1_0.93.R`).

이 스크립트는 `spi` 전체에 `normalize`, `standard`를 적용한 다음 분할한다. 대시보드용 `code/R/preprocessing.R`은 분할 후 학습셋의 min/max/mean/sd를 저장해 학습·테스트·사용자 입력에 같은 값으로 적용한다.

### 3.6 R Shiny 대시보드

대시보드는 지도 PNG 클릭 좌표 확인(`09_RShiny_UI_v1_지도클릭.R`), 같은 PNG를 plotly로 띄우고 댐 아이콘을 얹은 버전(`10_RShiny_UI_v2_Plotly.R`, `11_RShiny_UI_최종.R`), leaflet 실지도 버전(`preprocessing.R`, `etc/UI_v1.5.txt`) 순으로 바뀌었다. 최종 버전에서는 이미지 좌표 대신 댐 위경도(`dam_loc.csv`)로 leaflet 마커를 찍는다. 최종 버전은 유역·댐을 고르면 지도가 이동하고 `shinydashboard` valueBox에 유효저수량·총저수용량·높이를 띄운다. 댐을 고르면 유효저수량이 그 댐 값으로 고정되고 저수량 슬라이더 최대값이 총저수용량으로 바뀐다.

`code/R/preprocessing.R`

```r
    norm_precip_time <- normalize(input$precip_time, train_min_가조시간, train_max_가조시간)
    norm_avg_standard <- normalize(input$avg_standard, train_min_평균기온, train_max_평균기온)
    std_storage <- standard(input$storage, train_mean_저수량, train_sd_저수량)
    std_accum_precip <- standard(input$accum_precip, train_mean_누적강수량, train_sd_누적강수량)
    std_eff_storage <- standard(eff_storage_value, train_mean_유효저수량, train_sd_유효저수량)
    
    # Create a new data frame for prediction
    new_data <- data.frame(
      가조시간 = norm_precip_time,
      평균기온 = norm_avg_standard,
      저수량 = std_storage,
      누적강수량 = std_accum_precip,
      유효저수량 = std_eff_storage
    )
    
    # Make prediction
    prediction <- predict(rf_model, new_data, type = 'prob')
```

확률은 plotly 막대그래프로, 최대 확률 클래스는 텍스트로 출력하고, 지도 우측 하단에 SPI6 등급 기준표를 띄웠다.

## 4. 실험

### 4.1 실험 설정

- 검증 방식: 단일 홀드아웃. Oracle 단계는 `id` 임계값 분할, R 단계는 `createDataPartition(p = 0.9)` 층화 분할. 교차검증은 쓰지 않았다.
- 모델: Oracle `ALGO_RANDOM_FOREST`(기본 설정, `PREP_AUTO = ON`), R `randomForest`(기본 `mtry`).
- 하이퍼파라미터:

| 스크립트 | seed | ntree | 비고 |
|---|---|---|---|
| `07_랜포_트리수별_F1_비교.R` | 13 | 1~100 탐색 | 정확도·매크로 F1 곡선 |
| `08_랜포_표준화_최종_F1_0.93.R` | 분할 10, 학습 14 | 46, 59 | 주석: "seed=14, ntree=59 → 가뭄 F1 스코어 높음" |

### 4.3 비교 실험

Oracle 단계의 정확도는 `04_랜포_저수량포함_최종.sql` 머리 주석에 남은 결과 CSV 이름에 기록돼 있다.

| 결과 파일명 | 기간 | 저수량 평균 | 정확도 |
|---|---|---|---|
| `spi18-22랜포(90퍼)저수량평균X.csv` | 2018~2022 | 미포함 | 90% |
| `spi19-22랜포(89퍼)저수량평균X.csv` | 2019~2022 | 미포함 | 89% |
| `spi19-22랜포(88퍼)저수량평균O.csv` | 2019~2022 | 포함 | 88% |
| `spi랜포14-22(85퍼)저수량평균O.csv` | 2014~2022 | 포함 | 85% |

이 스크립트의 입력은 가뭄, 누적강수량, 계절, 가조시간, 평균기온, 행정구역, 저수량이다. 결과 CSV는 레포에 없어 행별 정확한 구성은 파일명 이상으로 확인되지 않는다.

- 학습 기간 확대(2019~2022 → 2014~2022)는 정확도를 올리지 않았다.
- 저수량 추가는 Oracle 단계에서 정확도 개선이 없었다(89% → 88%). R 최종 모델에서는 저수량을 유지했다.

변수 구성별 R 실험 기록은 데이터셋 단위로 남아 있다.

| 데이터셋 | 입력 변수 | 행 수 | 결과 |
|---|---|---|---|
| `SPI_랜포_테이블_최종.csv` | 12개 후보 | 32,239 | 개선 전 F1 0.925 |
| `댐제외_데이터.csv` | 누적강수량, 가조시간, 평균기온, 수위 | 81,239 | 점수 기록 없음 |
| `수위제외_데이터.csv` | 누적강수량, 가조시간, 평균기온, 저수량, 댐 | 47,131 | `08` 스크립트 입력, 파일명 기준 F1 0.93 |
| 5개 변수 + 스케일링 | 누적강수량, 저수량, 가조시간, 평균기온, 유효저수량 | 47,098 | 개선 후 F1 0.933 |

개선 전후는 변수 구성, 스케일링, 표본 수(32,239 → 47,098)가 동시에 바뀌었다. F1 0.925 → 0.933의 변화를 한 요인에 귀속시킬 수 있는 단일 변경 실험은 레포에 없다.

## 5. 한계와 향후 과제

1. 스케일링 누수: `08` 스크립트는 분할 전에 전체 데이터 통계로 스케일링했다. 랜덤포레스트라 점수 영향은 작겠지만 평가 절차로는 틀렸다. 대시보드 코드의 학습셋 기준 변환을 평가 스크립트에도 써야 한다.
2. 테스트셋 기반 선택: 트리 수(1~100)와 시드(seed 14, ntree 59)를 같은 테스트셋 F1로 골라 보고 점수가 낙관적으로 편향될 수 있다. 검증셋이나 k-fold 평균으로 골라야 한다.
3. 학습·서비스 불일치: 대시보드 모델은 seed 24, ntree 97로 발표 모델과 같다는 보장이 없다. 또 사용자 입력의 유효저수량은 표준화하지만 학습 데이터의 유효저수량은 원 단위로 둔다.
4. 시간 구조 미반영: 일자료를 무작위 분할해 인접 일자가 학습·테스트에 나뉘어 들어간다. 인접 일자의 SPI6와 6개월 누적강수량은 거의 같으므로 연도 단위 시간 분할이나 지점 단위 그룹 분할로 재평가해야 한다.
5. 피처-타깃 중첩: SPI6와 입력 누적강수량이 모두 약 6개월 강수량에서 나온다. 미래 시점 등급을 시차(lag) 변수만으로 맞히는 설정이 실제 예측 과제에 가깝다.
