2026년 4월부터 5월까지 「제2회 공정거래 AI·데이터 활용 공모전」 Track 2에 팀원 한 명과 참가했다. 공정거래위원회 의결서 500건으로 RAG 시스템을 만드는 과제였다. 나는 LLM 쪽(EXAONE LoRA 학습, 생성 평가)과 검색 인프라 일부(Contextual Chunking, 인덱스 정규화, 표 변환, 리랭커 결과 합산)를 맡았고, 임베딩 모델 비교와 리랭커 파인튜닝은 팀원이 맡았다.

티스토리에 세 편으로 나눠 쓴 개발 기록을 한 편으로 줄였다. 세부 실험과 코드는 원문 시리즈에 있다.

## 규칙이 설계를 먼저 정했다

의결서는 31,877개 청크로 미리 잘려서 제공됐고, 시스템은 질문마다 근거 청크 ID 정확히 5개와 답변을 돌려줘야 했다. 어기면 점수가 0이 되는 조건이 많았다.

| 규칙 | 어기면 |
|---|---|
| chunk_id 정확히 5개, 중복 불가 | 검색 0점 |
| 원본 chunk_id만 사용 (재청킹 금지) | 해당 청크 오답 |
| 문항당 30초 이내 | 문항 전체 0점 |
| 8B 이하 로컬 LLM | 실격 |

이 표를 README 맨 위에 두고 선택지를 하나씩 지워 나갔다. 결정 대부분이 여기서 나왔다.

- **임베딩 모델은 2개로 줄였다.** 5개 앙상블과 2개 앙상블의 R@5가 0.5402와 0.5420으로 사실상 같았는데, 응답 시간은 29.4초와 2.98초였다.
- **재청킹 대신 청크 앞에 맥락을 붙였다.** 실패 분석을 돌려 보니 100자 미만 짧은 청크의 실패율이 90%였고, 오답의 46.4%가 정답 바로 옆 청크였다. "과징금 | 1,000,000원" 같은 표 조각은 그것만 봐서는 어느 사건인지 알 수 없다. 청크를 자를 수 없으니 Anthropic의 Contextual Retrieval 아이디어를 가볍게 가져와 각 청크 앞에 문서 맥락을 붙여 색인했고, R@5가 8.45%p 올랐다.
- **리랭커 2종은 RRF로 합쳤다.** 점수 스케일이 다른 두 모델을 순위만으로 합칠 수 있어서다. 리랭커에 넘기는 후보 수는 6~8개일 때 가장 좋았다.

최종 구성은 BM25와 dense 임베딩 2종을 RRF로 합치고, 리랭커 2종을 다시 RRF로 합친 뒤, LoRA를 붙인 EXAONE 3.5 7.8B로 답을 만드는 구조다.

## 72.96점을 스스로 버린 이유

비공개 본평가 대신 같은 형식으로 278문항짜리 평가셋을 직접 만들었고, 모든 실험의 채택과 폐기를 이 점수로 정했다. 점수 흐름은 이랬다.

| 날짜 | 변경 | 합계 |
|---|---|---|
| 4/24 | 기준선 | 59.91 |
| 4/27 | + LoRA v1 | 63.82 |
| 4/29 | + 임베딩 개선 | 67.14 |
| 4/30 | + 리랭커 파인튜닝 | **72.96 (무효)** |
| 5/4 | 정규화 + 리랭커 2종 RRF | 67.39 |
| 5/5 | + LoRA 추가 학습 | 67.76 |

4월 30일 하루에 검색 점수가 5.8점 올랐다. 그 전까지는 하루에 1점 올리기도 힘들었다. 점검해 보니 누수가 두 군데였다.

- **임베딩 파인튜닝 (내 작업)**: 인접 청크를 구분하게 하려고 contrastive 학습용 triplet을 만들면서 평가셋 278문항 전체를 질문으로 썼다. 효과가 없어서 버렸는데, 지금 보면 효과가 없어서 다행이었다.
- **리랭커 파인튜닝 (팀원 작업)**: 평가셋을 8:2로 나눠 222문항으로 학습했다. 홀드아웃 검증은 했지만, 그 모델을 278문항 전체에 다시 돌린 점수가 72.96이었다.

두 누수 모두 평가셋이 하나뿐이고, 그 파일이 프로젝트에서 가장 품질 좋은 QA였기 때문에 생겼다. 학습 데이터를 찾는 사람 눈에 가장 먼저 보이는 재료였다. 점수가 오를 때 의심을 덜 한다는 것도 컸다.

72.96점은 무효로 처리하고, 학습에는 GPT-4o-mini로 따로 만든 1,500문항만 쓰도록 다시 돌렸다. 그 뒤로는 개발용과 최종 확인용 평가셋을 처음부터 나누고, 평가 질문뿐 아니라 정답 청크까지 학습에서 뺀다.

## LoRA에서 배운 것: 겉모양을 흉내 내면 무너진다

생성은 EXAONE 3.5 7.8B를 4bit로 올리고 LoRA(r 16, alpha 32)를 붙였다. 학습 데이터는 의결서 청크 1,500개에서 GPT-4o-mini로 질문과 답을 만들었고, 4시간에 0.40달러가 들었다.

| 버전 | 데이터 | 생성 점수 |
|---|---|---|
| 기준선 | LoRA 없음 | 28.53 |
| v1 | 자유 형식, 평균 88자 | **30.90** |
| v2 | 정답 패턴 문장 강제, 평균 54자 | 23.73 |
| v3 | 정형 시작 + 자유 설명, 평균 110자 | 24.43 |

평가셋 정답이 "이 사건에서 피심인은 ~"으로 시작하는 경우가 많아서 형식을 맞추면 토큰 F1이 오를 거라고 봤다. 결과는 반대였다. 질문 유형은 사실 확인, 법리 해석, 제재 내용 등 다양한데, 모든 답을 같은 틀로 시작하게 학습하니 질문과 상관없이 틀부터 채우는 답이 나왔다. 의결서 원문을 더 학습시킨 시도(CPT, 원문과 QA 혼합)도 v1보다 낮았다. 생성 쪽에서 가장 큰 개선은 결국 첫 LoRA였다.

## 다시 한다면

- 규칙 표를 먼저 만들고 모든 선택지를 그 표에 비춰 지운다.
- 평가셋은 처음부터 개발용과 최종용으로 나누고, 정답 청크를 학습 후보에서 뺀다.
- 하루에 점수가 크게 오르면 원인부터 찾는다.
- 정답 몇 개의 겉모양이 아니라 정답 분포를 따라가는 데이터를 만든다.
