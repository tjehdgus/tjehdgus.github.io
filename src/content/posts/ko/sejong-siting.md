## 초록

제5회 세종특별자치시 빅데이터 분석 아이디어 공모전(2024 가을)에서 공공 전기자전거 거치대의 행정동별 최적 입지를 선정했다. 1단계에서는 도로 24개, 417개 구간·방향의 통행속도(39,336행)로 감속률 기반 도로 스트레스 지수를 만들어 전기자전거 도입 근거를 정량화했다. 2단계에서는 버스정류장, 횡단보도, 정류장별 노선 수, 주차장 좌표를 행정동 폴리곤으로 나눈 뒤 동별로 K-Means를 돌리고, MCLP 커버리지가 70%를 넘는 8개 동은 MCLP 결과를, 나머지 6개 동은 OPTICS 결과를 채택했다. 정답 지도가 없는 문제라서 서울 지하철역·버스정류장·횡단보도로 K-Means 군집 중심을 뽑고, 실제 따릉이 대여소가 200m 안에 있는 중심의 비율로 변수 구성과 방법을 검증했다. 14개 동의 K-Means 실루엣 점수는 0.52~0.78, MCLP 커버리지는 21~88%였고, 프로젝트는 본선에 진출했다.

## 1. 문제 정의

과제는 세종시 공공 전기자전거 거치대를 행정동별로 어디에 둘지 고르는 것이고, 제안서 형식이라 두 질문에 답해야 했다.

1. 전기자전거가 왜 필요한가. 계획도시라 도로가 넓은 세종시에서 실제로 차량 속도가 떨어지는 구간이 얼마나 되는지 수치로 보인다.
2. 거치대를 어디에 둘 것인가. 행정동마다 후보 지점 좌표를 입력으로 받아 거치대 위치(군집 중심 또는 선택된 후보 지점)를 출력한다.

평가 지표는 단계별로 다르다.

```text
감속률(구간, 시간대)   = 1 - (시간대별 평균 속도 / 구간 최고속도)
실루엣 점수           = K-Means 군집 품질 (채택 기준 > 0.5)
커버리지 비율(%)      = 선택된 포인트가 포함된 군집의 데이터 수 / 전체 데이터 수 * 100
따릉이 근접 비율(%)   = mean( min_dist(군집 중심, 따릉이 대여소) < 0.002도 ) * 100
```

가장 큰 제약은 정답 라벨이 없다는 점이다. 세종시에는 아직 거치대가 없어 군집 결과가 맞는 위치인지 직접 확인할 수 없으므로, 서울 따릉이 대여소를 정답 대용으로 쓰는 검증 단계를 두었다.

## 3. 방법

### 3.1 전체 파이프라인

```text
[1단계: 도입 근거]
도로별 통행속도 xls 24개
  → 병합·요약행 제거·새벽 제외            (code/03~05)
  → 구간 최고속도 = 두 번째 최대값
  → 시점별 감속률 → 0~4 단계 지수, 4시점 합(0~16)   (code/24, 25)
  → 도로·구간·방향별 지수합 평균 → 지도  (code/26, 27)

[2단계: 입지 선정]
[검증] 서울 지하철역+버스정류장+횡단보도
  → K-Means(k=2763) → 군집 중심과 따릉이 대여소 거리 → 200m 근접 비율   (code/13~15)

[적용] 세종 정류장(노선 수 가중)+횡단보도+주차장
  → osmnx 행정동 폴리곤으로 동별 분리      (code/23, 32)
  → 동별 K-Means (k = 동별 어울링 대여소 수, 실루엣 > 0.5 확인)
  ├─ MCLP 커버리지 > 70%  → MCLP 결과 채택   (8개 동)
  └─ 그 외                → OPTICS 결과 채택 (6개 동)
```

- 1단계: "세종시 도로가 실제로 느려지는가"를 구간 단위 숫자로 바꾼다.
- 검증: 같은 종류의 변수로 뽑은 군집 중심이 오래 운영된 대여소와 겹치는지 본다.
- 적용: 동별로 K를 정하고, 커버리지가 충분한 동과 아닌 동을 다른 방법으로 처리한다.

### 3.2 구간 최고속도: 두 번째 최대값

감속률의 분모인 최고속도에 구간 최대값을 그대로 쓰면 한두 번 튄 기록이 기준이 되어 정상 구간도 크게 감속한 것으로 나온다. 그래서 구간별로 최대값보다 작은 값 중 가장 큰 값을 최고속도로 썼다.

`code/05_요일도로명구간시방향별 평균_최대값_차이 코드.py`
```python
def get_second_largest(group):
    result = {}
    for time_col in ['00분', '15분', '30분', '45분']:
        max_val = group[time_col].max()
        second_largest = group[time_col][group[time_col] < max_val].max()
        result[time_col] = second_largest
    return pd.Series(result)

second_largest_values = df2.groupby(['요일', '도로명', '구간', '방향']).apply(get_second_largest).reset_index()

final_df = pd.merge(day_time_mean_v, second_largest_values, on=['요일', '도로명', '구간', '방향'], suffixes=('_평균', '_최대값'))
```

평균은 시간대까지 묶고 최고속도는 시간대 없이 묶어, 같은 요일·구간·방향의 시간대별 평균이 하나의 최고속도와 비교된다.

### 3.3 도로 스트레스 지수

감속률을 5단계(0~4)로 바꾸고 00/15/30/45분 네 시점 점수를 더해 시간당 0~16점을 만든다. 첫 버전(`code/24`)에서는 최고속도가 30km/h 이하로 묶인 도로가 감속률이 낮아 "막히지 않는 도로"로 분류됐다. 자전거에는 조심해야 할 도로이므로 최고속도 30 이하면 4를 주는 규칙을 더했다.

`code/25_도로 스트레스 지수_어린이보호구역 적용.py`
```python
def calculate_index(avg, max_val):
    if max_val <= 30:
        return 4
    ratio = (1 - (avg / max_val)) * 100
    if ratio <= 20:
        return 0
    elif 20 < ratio <= 25:
        return 1
    elif 25 < ratio <= 35:
        return 2
    elif 35 < ratio <= 45:
        return 3
    else:
        return 4
```

이후 도로명·구간·방향별로 지수 합의 평균을 내 구간 하나에 값 하나를 붙이고(`code/26`), 도로 좌표 PolyLine에 색으로 칠했다(`code/27`). 발표 장표에서는 0~4 지수 대신 감속률을 보통(0~20%), 높음(20~35%), 매우 높음(35% 이상) 세 단계로 단순화해 보였다.

### 3.4 정답 대용 검증: 서울 따릉이

서울 지하철역, 버스정류장, 횡단보도 좌표를 합치고 서울 위경도 범위 밖의 점을 걸러 K-Means를 돌렸다. 군집 중심 하나를 대여소 하나로 보고 `n_clusters=2763`으로 잡았다. 따릉이 위치는 학습에 쓰지 않고 검증에만 썼다.

`code/14_k-means_정확도.py`
```python
# 클러스터 중심과 종속변수(따릉이 위치) 간의 거리 계산
distances_to_black = cdist(centroids, dependent_data[['lat', 'lng']])

# 각 클러스터 중심에서 가장 가까운 따릉이 위치까지의 거리 계산
min_distances_to_black = np.min(distances_to_black, axis=1)

# 클러스터 중심점 중에서 특정 거리 이내에 따릉이 위치가 있는 비율 계산 (약 200미터)
threshold_distance = 0.002
accuracy_centroid_within_threshold = np.mean(min_distances_to_black < threshold_distance)
```

이 비율이 높으면 교통 결절점 좌표의 밀도 중심이 공공자전거 수요 위치를 설명한다는 근거가 된다. 세종시에는 지하철이 없어 지하철역을 빼고 노선 수와 주차장을 더했다.

### 3.5 행정동 분리

`osmnx.geocode_to_gdf`로 "<동>, 세종시, South Korea"를 지오코딩해 폴리곤을 받고, 각 좌표가 폴리곤 안에 있는지 `shapely`의 `contains`로 판정해 동별 CSV를 저장했다(`code/32`). 대상 목록은 23개 동·읍이었고 저장된 파일은 21개다. 입지 선정 결과는 14개 행정동에 대해 정리했다.

### 3.6 동별 K-Means → MCLP 또는 OPTICS

- **K 설정.** 동별 면적·인구 차이를 반영하려고 기존 어울링 대여소 수를 K로 썼다. 실루엣 0.5 이상이면 채택, 아니면 가장 가까운 0.5 초과 K를 찾고, 없으면 OPTICS로 넘긴다.
- **MCLP.** K-Means 중심은 평균 위치일 뿐 수요 커버를 보장하지 않아, 반경 안의 수요를 최대한 덮는 MCLP를 적용했다. 발표자료의 정식화는 다음과 같다.

```text
maximize   sum_i y_i
subject to sum_j x_j <= K                      # 거치대 수는 최대 K (동별 어울링 대여소 수)
           y_i <= sum_{j : d(i,j) <= R} x_j    # 반경 R 안에 거치대가 있어야 수요 i가 커버됨
           x_j, y_i in {0, 1}
R: 기준 반경 200m(면적 순 중앙값인 새롬동 기준)에서 동별 인구밀도·면적으로 조정
```

- **OPTICS.** 커버리지가 낮은 동은 수요 점이 흩어져 고정 반경 방식이 맞지 않았다. 이런 동에는 도달 가능 거리(`ReachDist(p,q) = max(CoreDist(p), Distance(p,q))`)로 밀집 구간만 군집으로 잡는 OPTICS를 썼다.
- **최종 판단 기준.** `실루엣 > 0.5 그리고 커버리지 > 70%`이면 MCLP 결과를, 아니면 OPTICS 결과를 채택했다.

| 종촌동 | 0.52 | 59% | 0.72 | OPTICS |
| 한솔동 | 0.78 | 87% | 0.73 | MCLP |
| 해밀동 | 0.56 | 85% | 0.65 | MCLP |

**따릉이 대용 검증.** 검증 코드(`code/14`)는 레포에 있지만 실행 출력과 서울 입력 파일이 레포에 없어 근접 비율 값은 여기서 제시하지 않는다.

### 4.3 비교 실험

스트레스 지수 규칙은 레포의 전처리 파일로 다시 계산해 비교했다. 417개 구간 중 67개는 어느 시점이든 최고속도가 30 이하다.

| 변형 | 구간별 지수합 평균의 평균 | 중앙값 | 지수합 평균 12 이상 구간 | 4 미만 구간 |
|---|---|---|---|---|
| 감속률만 (`code/24`) | 8.58 | 9.94 | 100 | 73 |
| + 최고속도 30 이하 → 4 (`code/25`, 채택) | 9.37 | 10.18 | 140 | 70 |

방법 선택 기준을 바꿨을 때 결과는 다음과 같다.

| 선택 기준 | MCLP 채택 동 | 비고 |
|---|---|---|
| 실루엣 > 0.5만 | 14개 | 모든 동이 통과(최저 종촌동 0.52)해 변별력이 없음 |
| 실루엣 > 0.5 그리고 커버리지 > 70% (채택) | 8개 | 커버리지가 21~88%로 넓게 퍼져 실제 분기를 결정 |
| OPTICS 실루엣 기준 | 판단 불가 | OPTICS 실루엣도 0.61~0.73으로 14개 동 모두 0.5 초과. 실루엣만으로는 두 방법 사이 선택이 되지 않음 |

실루엣 점수는 동을 가르지 못했고, 분기를 결정한 것은 커버리지였다.

## 5. 한계와 향후 과제

- **거리 근사.** 위경도 0.002도를 200m로 본 유클리드 거리는 방향에 따라 반경이 다르다(서울 위도에서 위도 0.002도 약 220m, 경도 0.002도 약 180m). 하버사인 거리나 투영 좌표계(미터 단위)로 계산해야 한다.
- **무작위 기준선 부재.** 따릉이 근접 비율을 같은 수의 무작위 점이나 균등 격자와 비교하지 않았다. 서울 도심은 대여소가 촘촘해 기준선 없이는 비율의 높고 낮음을 판단할 수 없다.
- **경계 사례와 사후 임계값.** 아름동 커버리지는 장표상 70%로 `> 70%` 기준의 경계에 있는데 MCLP로 분류됐다. 70% 임계값도 결과를 본 뒤 정해졌다. 임계값과 경계 처리 규칙을 사전에 고정해야 한다.
- **스트레스 지수 근사.** 30 이하 규칙은 어린이보호구역 위치 매칭을 속도로 대신했다. 두 번째 최대값은 튀는 값이 둘 이상이면 무력하므로 분위수가 더 안전하다. 전처리 파일로 3단계 분포를 재집계하면 219/133/65로 발표 수치(190/140/87)와 달라, 발표의 집계 방식은 코드로 확인되지 않는다.
- **재현성.** 세종 동별 K-Means·MCLP·OPTICS 코드와 서울 검증 입력이 레포에 없고 스크립트가 로컬 절대경로에 의존한다. 동별 결과는 발표자료 기준이다.
